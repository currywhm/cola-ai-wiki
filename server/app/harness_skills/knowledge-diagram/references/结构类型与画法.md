# 结构类型与画法

## 一、五种结构类型（先选型，再填节点）

| 类型 | 什么时候用 | 例子 |
| --- | --- | --- |
| 层级 | 资料是「整体—部分」关系 | 制度 → 采购制度 / 报销制度 |
| 流程 | 资料讲先后顺序 | 立项 → 评审 → 采购 → 验收 |
| 对比 | 资料在比较两个对象 | A 方案 vs B 方案 |
| 因果 | 资料讲为什么发生 | 缺货 → 交期延长 → 客户流失 |
| 矩阵 | 资料有「两个维度」的分类 | 影响度 × 紧急度 |

选错类型的典型症状：节点之间关系说不清，只能靠堆平级节点硬凑。

## 二、节点命名规范

- 根节点：一个核心对象，≤ 10 字。
- 分支节点：3-6 个，互斥、同层次，≤ 8 字。
- 叶子节点：必须是具体事实、数据或结论，不能是分类名。
  - ✅「账期统一为 60 天 [2]」　❌「账期相关」
- 每个叶子都带出处编号。

## 三、文本画法约定

- 父子用 `├─`、`└─` 与缩进表示。
- 并列用同级缩进。
- 交叉引用写在节点下方，格式 `↔ 与「X」相关：关系说明`。
- 因果关系用 `→`，例如 `缺货 → 交期延长`。
- 对比关系用两列并列，不要强行塞进树里。

## 四、画之前先做三次检查

1. **互斥检查**：同一条内容会不会落进两个分支？会，说明分支切错了。
2. **层次检查**：有没有把「财务」和「财务里的报销细节」放在同一层？
3. **完整检查**：资料里最重要的 5 条信息，是否都在图上？

## 五、孤立节点怎么处理

资料里重要但归不进任何分支的内容，单独列在最后一组「孤立节点」。
不要为了好看硬塞进某个分支——那会让读的人误判归属关系。
同时在结尾写一句「孤立节点可能的归属方向」，供用户判断。
