# 会议纪要

## 目标
把一堆口语化、跳跃甚至重复的会议内容，压成一份**别人不用参会也能看懂、能看到自己要做什么**的纪要。
纪要的价值在「决议」和「待办」，不在复述谁说了什么。

## 前提与边界
- 只根据用户给到的材料整理。材料里没出现的责任人、时间，不要编，写「待定」并在末尾集中列出。
- 听不清或含义不明的口语（「那个」「就那样弄」），不要自行解释成具体结论，写进「待确认」 。
- 涉及薪酬、人事处分、未公开并购、诉讼等敏感内容时，正常记录，但在纪要开头加一行「本纪要含敏感信息，请限定范围内传阅」。

## 执行步骤
1. 提取会议要素：会议名称、时间、地点或形式、主持人、参会人、记录人、会议目的（一句话）。缺失的写「未提供」。
2. 按议题切段。议题名用会议里的原话或最贴近的名词短语，不要自创大词。
3. 每个议题下整理三类内容，按 `references/纪要规范.md` 的判定标准区分：
   - 讨论要点：只留影响结论的观点与关键数据，注明提出人；同一观点合并，不重复。
   - 决议：已经拍板的事。写成「确定……」，含决定内容、依据和生效条件。
   - 待办：谁、做什么、什么时候交、交给谁。
4. 标注争议：会上没达成一致的，写「未达成一致：一方主张……另一方主张……下次讨论前需补充……」，不要替会议下结论。
5. 待办表去重与去无主：责任人缺失的待办单独列出，写「待指派」；时间缺失写「待定」。
6. 结尾给「下次会议前需要准备的材料」和「待确认事项」。
7. 自检一遍：有没有把讨论说成决议？有没有把「我建议」写成「决定」？

## 输出格式
按 `assets/纪要模板.md` 的骨架输出。
用户要求交文件时，写成 Markdown 文件（文件名形如 `2026-09-16 产品评审会 纪要.md`），再在回答里列出决议与待办条数。

## 自检
- 每条决议是否写了「谁定的、定的是什么、什么时候生效」？
- 每条待办是否四要素齐全（事项、责任人、截止时间、交付物）？
- 有没有残留口语、口头语、「大概」「可能吧」这类不确定表述？
- 敏感信息是否加了传阅提示？

## 附带文件
- `references/纪要规范.md`：讨论／决议／待办的判定标准，以及六类常见整理错误。第 3 步用。
- `assets/纪要模板.md`：输出骨架。第 6 步之后按它排版。
