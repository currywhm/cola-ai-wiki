# 合同审阅

## 目标
把一份合同或协议，变成一份**能直接拿去谈判的审阅意见表**。
每条风险都要写清「原文怎么写的、会带来什么后果、改成什么」，而不是泛泛评价「条款需完善」。

## 前提与边界
- 立场决定风险方向。用户没说立场时，按「我方是付款方/委托方」来审，并在开头用一行注明这个假设，请用户核对。
- 只审用户给到的文本。没看到的条款一律算「缺失条款」，不要假设合同里有。
- 本技能给出的是商务与文本层面的审阅意见，**不是法律意见**。合同涉及金额重大、股权、担保、跨境、劳动关系、诉讼时效时，必须在结尾提示请执业律师复核。

## 执行步骤
1. 写合同速览：合同名称、类型（买卖／服务／委托／租赁／合作／保密／劳动…）、双方主体、标的、总金额与付款方式、期限、有多少附件。
2. 完整性核对：对照 `references/风险清单.md` 的十二类条款，逐类标记「有／没有／写了但不完整」。
3. 逐条精读已经写了的条款，给每条定风险等级：
   - 高：可能直接导致钱要不回来、责任无上限、失去救济手段（放弃诉讼、单方任意解除权、无上限赔偿）。
   - 中：口径模糊、时间不明、标准无法衡量、权利义务明显不对等。
   - 低：表述与格式问题，不影响实质权利。
4. 每个高风险与中风险条款写三行：原文摘录（可截断，但要保留关键措辞）→ 风险说明（对方会怎么用这条）→ 建议表述（一句可以直接替换的完整句子）。
5. 列缺失条款，每条写「缺了会怎样」和「建议补一条什么」。
6. 反向检查：站在对方立场，找出合同里对我方有利过头、对方很可能拒绝或事后主张显失公平的条款，标成「可让步项」。
7. 收尾给谈判优先级：必须先改（高）、可以让（可让步项）、知道就行（低）。

## 输出格式
按 `assets/审阅意见表.md` 的骨架输出。
用户明确要求交付文件时，把这份表写成一个 Markdown 文件（文件名形如 `《XX合同》审阅意见.md`），再在回答里给结论摘要。

## 自检
- 每条风险是否都写清了具体后果，而不是「建议进一步明确」这类空话？
- 建议表述是否是可以直接复制进合同的完整句子？
- 是否写了立场假设和免责说明？
- 有没有把「模板里常见、但这份合同其实已经写了」的内容当成缺失条款？

## 附带文件
- `references/风险清单.md`：十二类条款的审查要点、常见陷阱与提示问句。第 2、3 步逐类核对时读它。
- `assets/审阅意见表.md`：输出骨架。第 7 步之后按它排版。
