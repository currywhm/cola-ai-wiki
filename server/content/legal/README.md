# cola 知识库 · 合规文档（源文件）

这里放的是小程序里「关于 / 数据管理 / 隐私安全 / 小程序隐私保护指引 / AI 隐私政策 /
用户服务协议 / 软件许可及服务协议 / 会员服务条款与权益说明」的正文。

**内容归后端管**：小程序只负责渲染，改文案不用重新提交审核。运行时统一从数据库读，
部署时用 `python scripts/import_content.py`（或首次启动的自动导入）把源文件写进
`content_meta` / `content_entries` 三张表。

## 目录结构

```
content/legal/
  manifest.json        清单：版本号 + 条目元信息（数组顺序 = 展示顺序）
  entries/             正文，一篇一个 Markdown
    01-about.md        关于 cola 知识库
    02-data.md         数据管理
    03-privacy.md      隐私安全
    04-guide.md        小程序隐私保护指引（最完整的一份）
    08-ai-privacy.md   AI 隐私政策
    05-terms.md        用户服务协议
    06-license.md      软件许可及服务协议
    07-plan.md         会员服务条款与权益说明
```

本目录**不含配图**，所以没有 `assets/`：合规文档要保持纯文本可核对、可复制。

## 改文案

1. 直接编辑 `entries/*.md`（语法见下）。
2. 升 `manifest.json` 的 `version`（例如 `2026.09.20.1`），并同步该条的
   `updated_at` / `effective_at`，这两个日期会显示在页面顶部。
3. 在服务器上执行 `python scripts/import_content.py --slug legal`，或在本地
   `rsync` 到运行目录后重跑一次；导入脚本按指纹判断，内容没变会跳过。

改完价格、容量、额度这类数字时，**必须同时核对后端 `app/main.py` 里的
`MEMBERSHIP_LIMITS` / `PLAN_CATALOG`**，两边不一致就是上线风险。

额度写的是**积分**（不是问答次数）：`MEMBERSHIP_LIMITS[tier]['monthly_credits']` 与免费期
`FREE_CREDITS_AFTER_TRIAL` 是唯一口径，换算规则在 `app/services/credits.py`
（用户价 = deepseek-flash 真实成本 × `CREDIT_MARKUP`，1 积分 = `CREDIT_UNIT_YUAN` 元）。
模板句：一轮普通问答约 3～7 积分；单价为 deepseek-flash 官方价的 1.5 倍，加价倍率固定不变，但因官方单价分高峰/空闲两档，**扣分会随提问时段浮动**，文案里必须写明，不要写成「不随时段变化」。

## 占位符（随部署环境变化的信息）

正文里不写真实身份信息，用占位符，导入时从环境变量替换：

| 占位符 | 环境变量 | 留空时的行为 |
| --- | --- | --- |
| `{{operator}}` | `LEGAL_OPERATOR_NAME` | 退化为「cola 知识库小程序开发者（个人开发者）」，导入时打印告警 |
| `{{appid}}` | `WECHAT_APPID` | 退回内置的正式 AppID |
| `{{email_line}}` | `LEGAL_CONTACT_EMAIL` | 改为「小程序内联系客服」表述 |
| `{{icp_line}}` | `LEGAL_ICP_NUMBER` | 该句直接消失（不显示备案号） |

导入脚本会把没配置的项打印成 `[合规待办]`。**上线前这几项应当全部补齐**，
否则审核时看到的运营者信息是通用表述，容易被要求补充材料。

## 正文语法

和「使用技巧」共用同一套刻意收窄的 Markdown 子集：

| 写法 | 渲染成 |
| --- | --- |
| `## 小标题` | 段落标题（同时把下面的序号重新从 1 开始） |
| 直接写一行 | 正文段落 |
| `- 内容` | 圆点列表 |
| `1. 内容` | 带序号步骤（序号由后端重排） |
| `> 内容` | 浅底提示块 |
| `**加粗**` | 行内强调（标题里不生效） |

不支持表格、链接、图片——合规文案用列表表达即可，也避免小程序端渲染失真。

## 上线前必须同步的微信后台配置

小程序后台里填的内容要和 `entries/04-guide.md` 保持一致，否则审核会因为
「实际处理的信息与隐私指引不符」被驳回：

1. **用户隐私保护指引**（小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引）：
   - 收集的信息类型：微信 OpenID、用户主动设置的账号头像昵称、用户主动从个人相册选择的知识库头像、上传或选择的文件与图片、用户输入的文字。
   - 默认账号：登录只使用 OpenID，默认昵称为“微信用户”、头像为产品默认图；不得描述为自动读取微信头像昵称。
   - 权限：个人相册（仅取用户明确选中的图片，用于上传资料或设置知识库头像，不读取整个相册）、摄像头（拍照扫描文字）、选中的文件（微信文件选择器）。
   - 公开展示：未发布的知识库头像不公开；用户把知识库发布到广场后，头像、名称、简介、资料数量和发布者信息对所有用户可见。
   - 不勾选：位置、麦克风、通讯录、日历、微信运动。
   - 第三方共享：微信平台（登录/支付）、大语言模型服务、搜索服务（如启用）、云服务器。
2. **客服**：小程序后台开启客服并配置客服人员。「我的 → 联系客服」
   用的是 `open-type="contact"`，没配置客服时按钮点不开，注销与退款渠道就断了。
3. **服务类目**：工具类目（个人主体可选），与「资料整理 / 问答工具」的产品定位一致。
4. **备案**：完成小程序备案后把备案号写进 `LEGAL_ICP_NUMBER`，再重跑导入脚本。
5. **虚拟支付**：会员价格必须与后台配置的道具价格一致，改价要两边同时改。
6. **模型厂商或服务器地域变化**：如果换成别的模型服务商、启用境外模型，或服务器迁到境外，
   `04-guide.md` 与 `08-ai-privacy.md` 的第三方、存储和出境相关章节必须同步改写，
   并在启用前另行告知、依法取得同意。
