# 数据表分析

## 目标
从一堆数字里给出**能落地、可追溯的结论**：每个结论后面都要跟具体数字，每个异常都要给出可能原因与下一步核实动作。
不允许出现「整体表现良好」这类没有数字的废话。

## 前提与边界
- 先确认口径，再谈分析。指标定义、时间范围、单位、统计范围（是否含子公司、是否含税）不明确的，在开头单列「口径假设」，不要默默替用户定。
- 只对给到的数据下结论。数据没覆盖的维度，写「本次数据无法判断」，不要用行业经验补。
- 相关不等于因果。看到两个指标同向变化，只能写「同向变化，需进一步验证」，除非用户给了可解释的机制。

## 执行步骤
1. 写数据概况：多少行、时间跨度、有哪些字段、单位是什么、有没有缺失值和明显可疑值。
2. 核口径：对每个要用的指标，写出它的定义与计算方式（如「毛利率 =（收入-成本）/ 收入」）。口径不明的地方列成待确认项。
3. 看基本盘：总量、期间变化（环比、同比，注明对比基期）、最大与最小值、区间分布。
4. 找异常：对照 `references/分析口径与陷阱.md` 的六类陷阱，找出突变点、离群值、口径断裂、占比异常，每个异常写「现象 → 可能原因（至少两个）→ 怎么核实」。
5. 看结构：拆占比与贡献度，找出「谁贡献了主要增长、谁在拖后腿」，做贡献分解（总量变化 = 各分项变化之和）。
6. 找关系：只对用户关心的组合做对比，写清是同步变化还是有先后顺序，不直接下因果结论。
7. 出结论与建议：3-6 条结论，每条格式「结论（数字）→ 依据（哪几列／哪几行）→ 建议动作」。建议要能被执行，写清谁做什么、看什么指标验证。
8. 写数据局限：这份数据不能回答什么。

## 输出格式
按 `assets/分析报告模板.md` 输出。
用户要求交文件时写成 Markdown 文件（形如 `××数据 分析报告.md`）；如果用户明确要表格产物，再写一个 CSV／Markdown 表格文件。

## 自检
- 每条结论是否都带数字与依据？
- 异常是否给了至少两个可能原因，而不是直接下结论？
- 是否把口径假设和待确认项写在最前面？
- 有没有把「同向变化」写成「导致」？

## 附带文件
- `references/分析口径与陷阱.md`：常用指标口径、六类数据陷阱与核实问句。第 2、4 步用。
- `assets/分析报告模板.md`：输出骨架。第 8 步之后按它排版。
